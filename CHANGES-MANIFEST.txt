WHAT CHANGED (beta 29)
----------------------
1. SPELL "LEARNED FROM" (new MmeDatabase.GetSpellSourceLines):
   - Teaching items found by scanning for ABILITY 42 (LearnSp) directly,
     NOT from the denormalized Spells."Learned From" field. That field is
     incomplete (stock: 217 ability-42 slots vs 205 "Item #" refs) and is
     often not regenerated on custom realms. Cross-checked: 207/207 of
     the existing refs agree with the ability scan, 0 mismatches.
   - NPC refs resolved to jumpable Monster lines.
   - Textblock-taught spells: the teaching NPC is traced
     TBInfo."Called From" -> "Room m/r" -> Rooms."NPC" (the NPC is not in
     the textblock itself), plus the quest command phrase, the required
     checkitem, and the class/minlevel gate (class number -> class name).
2. CLICK-THROUGH FIXES:
   - The Spells detail pane had NO MouseDoubleClick handler; wired to the
     existing DetailText_MouseDoubleClick.
   - NavigateFromLine's monster regex was anchored "^Monster:", which the
     "(learn) " prefix would have broken; anchor relaxed.
   - "Item:" lines were never jumpable anywhere (logged divergence). Added
     MainViewModel.ParseItemRefLine (pure/static) + the window routes it
     through the existing DoEquipJump (weapons/armour/sundry routing and
     the "clear the filter?" prompt reused). Also applies to dossier
     lines, so monster drop "Item:" lines are now clickable.
3. EQUIPMENT CALCULATOR — NO CODE CHANGE NEEDED; DOC FIX ONLY.
   The "accumulation loops still pending" text was stale README copy
   (it also still claimed 693 tests). The calculator shipped in session
   23: EquipmentStatsService.cs, 918 lines, class/race ability scans,
   encumbrance-first, bless, equipped+carried loop, per-slot tips; ledger
   records "Ported (session 23) + real-db anchors". New pin
   EquipmentCalc_AccumulatesWornItemIntoDerivedStats proves it (equipping
   padded vest 332 raises encumbrance AND AC; tips name the item).
   README corrected.
